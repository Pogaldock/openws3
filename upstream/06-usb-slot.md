**What:** `usb_isr` copies each OUT report into `rx` and sets `rx_pending`, even when a command is already waiting. A second report that arrives before the main loop takes the first overwrites it, so a **stop can be lost** (for example a stop followed quickly by a status ping). A short report also leaves the previous report's bytes in place.

**A fix (in WS3 Unlocked):** one waiting command, the first one wins, and a later one is dropped unacknowledged; the host resends a command that is not acknowledged within about half a second; the unit runs a given sequence number only once, so a resend after a lost acknowledgement does nothing twice; short reports are zero-filled.
